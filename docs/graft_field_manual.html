01 Orientation

The SWE challenge & environment

The Google Gemma 4 Developer Agent Competition evaluates agents against real-world GitHub issues across Python repositories (e.g. Textualize/rich, fastapi/fastapi). The agent operates completely offline in Docker containers, generating unified git diffs that must pass hidden unit tests.

The Core Constraints

ConstraintValueEngineering Impact
Evaluation Tasks~120 tasksEvaluated sequentially in a shared 12-hour session
Per-Task Time Budget~5.0 minutesAverage active LLM reasoning time allowed per issue
Compute Hardware4x NVIDIA L496 GB total VRAM; requires Tensor Parallelism = 4
Base Model Checkpoint31B INT4gemma-4-31b-it-qat-w4a16-ct (16–18 GB weight VRAM)
Network ConnectivityAir-gappedZero internet access; no pip install or external APIs
Submission Manifest< 100 KB targetStrictly declarative YAML and Markdown prompts (ADK)

The Dual-Container Lifecycle & Boundary Crossings

The evaluation harness (swegemma) executes a strict two-phase containerized lifecycle governed by explicit serialization contracts:

  • Phase 1 (Container A - Agent Sandbox): Agent starts in /workspace at the baseline git commit. The agent uses 9 sandboxed tools to read files, run bash commands, edit code, and call submit_patch().
  • Phase 2 (Container B - Verification Sandbox): A pristine container extracts agent_patch from Container A, strips edits to protected test directories (e.g. tests/, conftest.py), applies the patch using a 4-pass fallback engine, applies the hidden ground-truth test_patch, and runs pytest with JUnit XML scoring.
Context Packet (Step 0)

Container A receives: verbatim GitHub problem statement, offline filesystem mounted at /workspace pinned to base_commit, OpenAPI JSON schemas for the 9 tools, and runtime environment variables (SWE_BENCH_TASK_ID, virtualenv).

Container B Rejection Rules

Patches are automatically rejected with score 0.0 if they: (1) fail py_compile syntax checks; (2) fail 4-pass patch -p1 application; (3) modify test files exclusively; or (4) break existing PASS_TO_PASS regression tests.

Check yourself

Why are edits to tests/ or pytest.ini stripped in Container B?

In SWE-bench evaluation, an agent must fix the library source code. Stripping test edits prevents trivial hacking of the test suite.

02 Part I · Architecture & Harness

Model serving & reasoning tokens

Running Gemma 4 31B inside an offline competition requires balancing model quantization, KV-cache utilization, and reasoning token budgets to prevent forward-pass latency from breaching task time ceilings.

Model Quantization: W4A16 QAT

Unquantized Gemma 4 31B (bfloat16) requires ~62 GB of VRAM just to hold model weights. On 4x NVIDIA L4 GPUs (24 GB each, 96 GB total), unquantized weights leave minimal room for KV-cache under 32k context lengths.

In Graft

We deploy gemma-4-31b-it-qat-w4a16-ct (Quantization-Aware Trained 4-bit integer weights with 16-bit floating point activations). Weights consume only ~16–18 GB total (~4.5 GB per GPU), leaving over 19 GB of VRAM per GPU for high-throughput KV-caching with gpu_memory_utilization = 0.90.

Reasoning Token Dynamics

Gemma 4 natively generates structured reasoning thoughts bounded by <|channel>thought...<channel|>. While thinking improves multi-hop code reasoning, unconstrained thinking blocks (e.g. 2,048–4,096 tokens) consume 25–45 seconds per turn. With ~15 turns per task, thinking tokens alone would consume 8+ minutes, guaranteeing a fatal session timeout.

Turn Latency = (Tokensthought + Tokenstool_call) / Generation Speed ≈ (1024 + 150) / 45 tps ≈ 26.0s
At thinking_budget: 1024, a 15-turn task spends ~390s (6.5 min) total across inference and tool execution.

03 Part I · Architecture & Harness

The nine sandboxed tools

In SWE-gemma, the agent does not execute arbitrary host functions. It interacts exclusively through 9 native sandboxed tools registered in ToolRegistry.

Tool NameCategoryBudget CountedKey Constraints & Behavior
run_commandExecutionYesExecutes bash command in /workspace. Capped at 5,000 chars output; 120s timeout.
read_fileFilesystemYes1-indexed line slicing. Capped at 150 lines and 10,000 chars per call.
edit_fileFilesystemYesExact string replacement (requires unique match of old_string).
write_fileFilesystemYesWrites new file in /workspace. Path traversal (e.g. /tmp) blocked.
search_similar_codeGraph AIYesCosine similarity lookup over AST and repository embeddings.
get_code_neighborsGraph AIYesReturns callers and callees in precomputed repository NetworkX graph.
get_code_subgraphGraph AIYesExtracts induced subgraph connecting multiple symbols.
get_statusTelemetryNo (Free)Returns elapsed seconds, remaining seconds, tool calls, and turns.
submit_patchLifecycleNo (Free)Runs git add -N . && git diff HEAD and captures the patch.
Tool Contract Hazard: Parameter Mangling & 1-Strike Fallback

edit_file requires three strictly ordered arguments: filepath, old_string, and new_string. In our dev runs, multiline docstrings containing parentheses and quotes caused Gemma 4 to emit argument keys like ,old_string: inside the string scalar, triggering 39 consecutive failed tool calls.

The 1-Strike Rule: If edit_file fails even once, the agent is barred from retrying edit_file and must immediately apply the fix using a deterministic Python one-liner via run_command:

python -c "p = open('path/to/file.py').read(); open('path/to/file.py', 'w').write(p.replace('''OLD''', '''NEW'''))"

05 Part II · Operational Discipline

Pacing envelopes & zero-timeout rule

In SWE-bench, the single most destructive failure mode is not a syntax error—it is an over-verification timeout. A plausible patch submitted at minute 4 earns points; timing out at minute 6 earns exactly 0.0.

The Stop-and-Submit Protocol

In Graft

Section 5 of [`submission/prompts/system.md`](file:///c:/Users/acquayefrank/Code/graft/submission/prompts/system.md) codifies the Mandatory Stop-and-Submit Rule:

"The moment your reproduction script or target test passes, STOP! Do NOT write additional tests. Do NOT make secondary refactorings. Additional turns risk fatal session timeout and forfeiting all points."

In our baseline run, 43.3% of tasks failed due to fatal session timeouts. Implementing the Stop-and-Submit rule and a strict 4.5-minute operational ceiling slashed fatal timeouts to 13.3%, lifting resolution rate from 36.7% to 53.3%.

06 Part II · Operational Discipline

Scratchpad isolation & path traversal

How temporary reproduction scripts caused silent 0-score grading failures, and how workspace isolation eliminated them.

The Path Traversal Trap

In standard bash environments, engineers write temporary scripts to /tmp/repro.py. In SWE-gemma, write_file enforces strict container sandboxing: passing /tmp/... immediately fails with Path traversal detected. If the agent instead writes repro.py in /workspace, git add -N . includes the script in agent_patch, contaminating the submission.

The Fix in Graft

Graft standardized on build/repro.py. The harness setup automatically adds build/ to .git/info/exclude. Scripts written to build/repro.py are completely invisible to git diff HEAD, preventing diff pollution.

07 Part II · Operational Discipline

The clean-exit termination handshake

In SWE-gemma, calling submit_patch() does not terminate the container. The runner requires a specific conversational event to break its execution loop.

The Runner Termination Condition

Inside [`swegemma/harness/agent_runner.py`](file:///c:/Users/acquayefrank/Code/graft/build/wheels/swegemma-0.2.11-py3-none-any.whl):

if (
    event_author not in {'user', 'harness', 'system', 'tool'}
    and has_text
    and not has_function_call       # <--- MUST HAVE ZERO TOOL CALLS
    and context.patch_submitted
):
    logger.debug('Agent submitted patch and returned final completion message; terminating.')
    break

If the model outputs text like "I've submitted the patch. I'll stop now" but includes another tool call (such as submit_patch()), has_function_call remains True! The runner continues until the 6.0-minute timeout kills the task.

In Phase 6 Prompt

We codified the Mandatory Clean-Exit Protocol: immediately after submit_patch() returns status: ok, the agent MUST output text only with zero tool calls.

10 Part IV · Trace Post-Mortems

Four critical trace post-mortems

Detailed autopsy of the four primary failure modes discovered during trace inspection of the 14 failed tasks in dev30.

1. The Termination Deadlock (`fastapi_13920`)

What happened: A 4-line bug in FastAPI type dependencies. The agent found the bug, fixed it, and called submit_patch() at Turn 37. Then it stated "I've submitted the patch. I'll stop now"—but emitted submit_patch() tool calls for 36 consecutive turns until killed at 6.0 min!

Lesson: Open-weight LLMs must be explicitly instructed to output zero tool calls after submitting.

2. Tool Parameter Mangling (39 failed calls across `rich_4076`, `3052`, `3675`)

What happened: When editing docstrings with parentheses and quotes, Gemma 4 emitted argument names like ...,old_string: directly into string scalars. edit_file failed 11–16 times in a row with missing mandatory parameter: old_string.

Lesson: Enforce a 1-strike fallback: if edit_file fails once, immediately execute a Python one-liner via run_command.

3. Zero-Telemetry Turn Blindness (`rich_3063`, `rich_3935`)

What happened: Prompt instructed "Check get_status if you reach Turn 10". In all 30 tasks, get_status was called 0 times. The models spent 15+ turns rewriting broken repro scripts without realizing time was expiring.

Lesson: Models cannot count turns. Telemetry triggers must be tied to failure events (e.g. repro fails on attempt 1).

4. Single-Character Omission (`fastapi_15588`)

What happened: The agent fixed SSE newline splitting by checking if "\n" in value:. Hidden unit tests also passed carriage returns (\r and \r\n), failing assertion.

Lesson: Pre-flight syntax and edge-case testing prevents single-character test failures.

Glossary

Key systems and machine learning terms used throughout the manual.

SWE-bench
Standardized benchmark evaluating LLMs on resolving real-world GitHub issues via executable git diff patches.
ATIF (v1.7)
Agent Trajectory Interchange Format: structured JSON representation of an agent's multi-turn thoughts, tool calls, and observations.
ADK
Agent Development Kit: Google's framework for compiling hermetic, declarative agent specifications (SandboxedAgentConfig).
swegemma
The official competition orchestrator managing Docker container lifecycles, tool execution, and JUnit scoring.
vLLM
High-throughput LLM serving engine featuring PagedAttention and multi-GPU tensor parallelism.
Stop-and-Submit
Operational protocol commanding an agent to immediately submit upon repro test success, avoiding fatal over-verification timeouts.
Clean-Exit
Protocol requiring a text-only turn with zero tool calls after submit_patch(), satisfying the runner's termination condition.
W4A16 QAT
Quantization format with 4-bit integer weights and 16-bit float activations, reducing Gemma 4 31B memory footprint to ~16 GB.
